## 后处理：绿幕抠图 + 差异提取分层（同日补齐）

需求对应 `docs/素材生成描述.md` 第九节（出图后处理清单）。

- 脚本：`tools/postprocess.py`（全流程）、`tools/verify_looks.py`（搭配验证）
- 产出：`res/<品类>/<品类>_<编号>.png`（按品类统一裁切）、`res/full/<品类>/*.png`（1024×1536 已定位整层）、`res/manifest.json`
- 验证图：`分层审计.png`（33 层各合成一格）、`搭配验证.png`（4 套完整搭配）

### 三条踩坑记录（都很值钱）

1. **抠图不能用「与背景色的 RGB 距离」算 alpha。** 深色前景与绿幕的 L1 距离可能很小（黑夹克仅 159，而肤色 428），会被误判成半透明背景 → 后续差异提取把它整片排除（top_05 只提出 1.5 万 px，正确值 14.9 万）。
   **正解：用「绿幕优势度」`ge = g - (r+b)/2`**，背景 ge≈131，肤色/白/黑都≈0，与前景颜色无关。
2. **青绿色衣物会被 ge 法误伤**（青绿旗袍 ge≈52 → alpha 0.6）。修法：对 `alpha∈[0.35,0.90]` 区域做 **2 圈腐蚀**，仍有核心的是「整块绿色衣物」（→ alpha 置 1），只有 1~2px 宽的抗锯齿边缘腐蚀后归零。
3. **绿幕有约 0.6% 的像素带 0.02~0.4 的假 alpha**，叠在别的层下面会显出淡淡脏痕。修法：绿色衣物修复之后，`alpha < 0.45` 一律清零（顺序不能反，否则会削掉旗袍）。
4. **碎块过滤阈值不能低于 800px**：模型在无关部位会有细微漂移，阈值太小会让鞋层/上衣层抓进肩膀高度的碎块，裁切矩形直接失控。

### 其他结论

- **差异提取成立**：`|生成图 − 素体|.max(2) > 12`，配合开运算(3×3)+闭运算(5×5)+连通域≥800px，即可得到已经定位好的部件层，**无需任何缩放/对齐**。33 层实测零背景漏入、零内容越界。
- **对齐精度**：所有层与素体的前景包围盒偏差 ≤1px，画布统一 1024×1536。
- **压缩**：原始 66.66MB → 192 色量化后 **2.06MB**（主包上限 4MB）。
- **⚠️ 文档第十节 z 序有误**：写「shoes(5) → bottom(15) → 素体身体(10)」，但鞋若画在素体之下会被素体的脚盖住、直接看不见。实际可用顺序是 `body → shoes → hair → bottom → top/dress → acc`，已写进 `res/manifest.json` 的 `render_order`。**该文档尚未修改，待用户确认。**

### 差异提取失效的两件（已知，非 bug）

- `top_02` 白色短袖T恤：与素体的白色打底衫几乎同色，diff>60 只有 3171px，提取出的层只有 1546px（只剩草莓图案）。**视觉上不影响**（底模本来就是白T），但要单独换色才需要重出。
- `hair_01` 栗棕齐肩短发：与素体底发同色同型，几乎是空层。它是默认发型槽，不需要独立层。
